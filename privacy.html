Privacy Policy

workspace-storage is a personal file-storage integration operated by the owner of the GitHub account saipr0.

Data accessed and why

The application uses Google Drive's drive.file permission to create and manage files and folders created by or explicitly authorized for the application. It processes file contents and associated metadata, including names, sizes, identifiers and modification times, to perform the owner's requested storage operations.

Google OAuth access and refresh tokens allow rclone to access the authorized Drive account without asking for the account password. The application does not request access to Gmail or Google Contacts.

Storage and protection

Rclone's crypt feature encrypts file contents, filenames and subfolder names on the owner's device before uploading them to Google Drive. The enclosing workspace folder name, encrypted object sizes and some other metadata are not hidden from Google.

Decrypted files may be stored or cached on the owner's server or other devices when used. Rclone configuration, OAuth tokens and encryption settings are stored on devices configured by the owner. Rclone's default password obfuscation in its configuration is not strong encryption; access to that configuration must be protected.

Operational logs may contain file paths, timestamps and error details. Configuration, credentials and private file contents are not intended for publication in this website or its repository.

Use and sharing

Google user data is used only to provide the requested personal file-storage functionality. The application does not sell this data, use it for advertising, or use it to train artificial intelligence models. Google Drive processes and stores the uploaded encrypted data as the storage provider.

The owner may separately choose to share files through their storage tools. Such sharing is controlled by the owner.

workspace-storage's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Retention, deletion and revocation

Files remain in the configured storage until the owner deletes them. Local copies, caches, Drive trash, file revisions and independently configured backups may retain data until separately removed or expired under their retention settings.

The owner can revoke the application's Google access in Google Account connections. Revocation stops future authorized access but does not itself delete existing files or local copies. The owner can remove stored credentials from their devices and delete cloud files separately.

This public website

These informational pages contain no analytics scripts, advertising, forms or application cookies. GitHub Pages hosts this site and may process technical request information, such as IP addresses, under GitHub's Privacy Statement.

Questions and updates

Contact the operator through workspace-storage GitHub issues. Issues are public; do not submit private files or credentials. Material changes to this policy will be reflected on this page with an updated effective date.
